Wake on LAN da fuori casa con UpSnap e Tailscale

Prerequisiti

  • Il PC da accendere già configurato per il Wake on LAN (BIOS, scheda di rete, avvio rapido disattivato) e collegato al router col cavo;
  • Un secondo dispositivo sempre acceso con Linux: un server di casa, un mini PC, un Raspberry Pi o una macchina virtuale in modalità bridge su un altro computer;
  • Docker installato su quel dispositivo.

Docker Desktop su Windows o macOS non va bene: il container non riesce a mandare il pacchetto sulla rete di casa.

1. Sul PC da accendere: MAC address

Apri PowerShell e lancia:

ipconfig /all

Cerca la scheda Ethernet, non quella Wi-Fi o virtuale, e annota Indirizzo fisico e Indirizzo IPv4. Assegna al PC un IP fisso nel router, così UpSnap lo ritrova sempre.

Se non l'hai ancora fatto, disattiva l'avvio rapido. Da PowerShell come amministratore (disattiva anche l'ibernazione):

powercfg /h off

2. Sul server: installa Tailscale

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Apri il link che compare e accedi con lo stesso account che usi sul telefono. Poi annota l'indirizzo Tailscale del server, quello che inizia con 100.:

tailscale ip -4

3. Sul server: crea il file di UpSnap

Se Docker non c'è ancora, installalo con lo script ufficiale:

curl -fsSL https://get.docker.com | sudo sh

Crea la cartella di UpSnap ed entraci:

mkdir -p ~/upsnap && cd ~/upsnap

Crea il file di configurazione:

cat > docker-compose.yml <<'EOF'
services:
  upsnap:
    container_name: upsnap
    image: ghcr.io/seriousm4x/upsnap:5
    network_mode: host
    cap_drop:
      - ALL
    cap_add:
      - NET_RAW
    environment:
      - TZ=Europe/Rome
    volumes:
      - ./data:/app/pb_data
    restart: unless-stopped
EOF

network_mode: host è indispensabile: senza, il magic packet resta chiuso dentro Docker e non arriva al PC.

4. Avvia UpSnap

sudo docker compose up -d

Controlla che giri. Il container upsnap deve risultare Up:

sudo docker ps

Se il firewall del server è attivo, apri la porta 8090, altrimenti la pagina non si apre dagli altri dispositivi:

sudo ufw allow 8090/tcp

5. Crea l'account amministratore

Dal terminale del server, con la tua email e una password robusta:

sudo docker exec upsnap /app/upsnap superuser upsert tua@email.it PasswordRobusta

6. Primo accesso e PC da accendere

  1. Da un altro PC di casa apri http://IP_DEL_SERVER:8090
  2. Accedi con l'account appena creato
  3. Aggiungi un nuovo dispositivo: nome, IP e MAC address del passaggio 1
  4. Salva. Nella dashboard il PC compare acceso o spento, a seconda dello stato

7. Accendere il PC da fuori casa

  1. Sul telefono attiva Tailscale
  2. Nel browser apri http://100.x.y.z:8090, con l'indirizzo Tailscale del passaggio 2
  3. Accedi e premi il pulsante di accensione del PC

Fai la prova vera con il Wi-Fi del telefono spento, in rete mobile.

Non aprire porte sul router. UpSnap si raggiunge solo da Tailscale: esporlo su internet significherebbe lasciare a chiunque un pannello che accende i computer di casa.

Fermarlo e riavviarlo

UpSnap riparte da solo a ogni riavvio del server. I comandi vanno lanciati dalla cartella upsnap:

cd ~/upsnap

Per fermarlo:

sudo docker compose stop

Per riavviarlo:

sudo docker compose start

Per aggiornarlo:

sudo docker compose pull && sudo docker compose up -d

Per eliminarlo, insieme a dispositivi e account:

sudo docker compose down && sudo rm -rf ~/upsnap/data

Troubleshooting

  • UpSnap manda il pacchetto ma il PC non si accende: prova senza UpSnap, direttamente dal terminale del server. Se non si accende nemmeno così, il problema è nel PC (BIOS, scheda di rete, avvio rapido): 
    sudo apt install wakeonlan
    wakeonlan AA:BB:CC:DD:EE:FF
  • Si accende dalla sospensione ma non da spento: avvio rapido ancora attivo, oppure nel BIOS è attiva l'opzione ErP o Deep Sleep, che toglie corrente alla scheda di rete
  • Funziona in casa ma non da fuori: controlla che Tailscale sia attivo sul telefono e che il server risulti connesso nell'app
  • Il server è una macchina virtuale e il pacchetto non arriva: imposta la scheda di rete della VM in modalità bridge, non NAT
  • La pagina su :8090 non si apre: controlla la regola del firewall al passaggio 4, poi leggi i log con sudo docker compose logs --tail 50
  • Dopo un blackout il PC non risponde più: con alcune schede madri bisogna accenderlo e spegnerlo una volta a mano
