Installare Pi-hole su Docker in Windows

Prerequisiti

  • Windows 10 22H2 o Windows 11 23H2, o versioni successive, anche Home;
  • 8 GB di RAM;
  • Virtualizzazione attiva nel BIOS;
  • WSL installato. Se non ce l'hai, apri PowerShell come amministratore, lancia il comando qui sotto e riavvia il PC:
wsl --install --no-distribution

Se WSL ce l'hai già, il comando si limita ad aggiornarlo.

1. Scarica Docker Desktop

Apri PowerShell (come utente normale):

winget install -e --id Docker.DockerDesktop

Se ti chiede di accettare i termini, scrivi Y e premi Invio.

Avvia Docker Desktop dal menu Start, accetta le condizioni e aspetta che in basso a sinistra compaia Engine running (se non dovesse funzionare, prova innanzitutto a riavviare la macchina).

Chiudi e riapri PowerShell, poi controlla che Docker risponda:

docker version
docker compose version

2. Scarica il container di Pi-hole

Crea la cartella di Pi-hole ed entraci:

mkdir $HOME\pihole; cd $HOME\pihole

Crea il file di configurazione. Prima di incollarlo, sostituisci CAMBIAMI, evidenziato qui sotto, con la password che vuoi usare per il pannello:

@'
services:
  pihole:
    container_name: pihole
    image: pihole/pihole:latest
    ports:
      - "53:53/tcp"
      - "53:53/udp"
      - "80:80/tcp"
      - "443:443/tcp"
    environment:
      TZ: 'Europe/Rome'
      FTLCONF_webserver_api_password: 'CAMBIAMI'
      FTLCONF_dns_listeningMode: 'ALL'
    volumes:
      - pihole_data:/etc/pihole
    cap_add:
      - SYS_NICE
    restart: unless-stopped
volumes:
  pihole_data:
'@ | Set-Content docker-compose.yml

Scarica l'immagine:

docker compose pull

Esecuzione

Prima di avviarlo, controlla che la porta 53 sia libera. Se questo comando mostra un risultato, la porta è occupata e Pi-hole non partirà (vedi Troubleshooting):

Get-NetUDPEndpoint -LocalPort 53

Avvia Pi-hole:

docker compose up -d

Controlla che giri. Il container pihole deve risultare Up, e dopo qualche secondo healthy:

docker ps

Trova l'IP del PC, alla voce Indirizzo IPv4:

ipconfig
  1. Apri http://IP_DEL_PC/admin, oppure http://localhost/admin dallo stesso PC
  2. Accedi con la password che hai scelto al punto 2

Assegna al PC un IP fisso nel router, poi imposta quell'IP come DNS su un dispositivo o sul router. Se il PC si spegne, chi usa Pi-hole come DNS smette di navigare.

Fermarlo e riavviarlo

Pi-hole riparte da solo ogni volta che apri Docker Desktop. I comandi vanno lanciati dalla cartella pihole:

cd $HOME\pihole

Per fermarlo:

docker compose stop

Per riavviarlo:

docker compose start

Per aggiornarlo all'ultima versione:

docker compose pull; docker compose up -d

Per eliminare il container e le impostazioni:

docker compose down -v

Troubleshooting

  • "docker" non è riconosciuto: chiudi e riapri PowerShell dopo l'installazione
  • Docker Desktop segnala la virtualizzazione disattivata: attivala nel BIOS, la voce si chiama Intel VT-x o AMD-V a seconda del processore
  • La porta 53 è già occupata: di solito è la Condivisione connessione Internet di Windows. Disattivala da PowerShell come amministratore con Stop-Service SharedAccess; Set-Service SharedAccess -StartupType Disabled, poi rilancia docker compose up -d
  • La porta 80 è già occupata: apri docker-compose.yml e cambia "80:80/tcp" in "8080:80/tcp", poi apri il pannello su http://IP_DEL_PC:8080/admin
  • Gli altri dispositivi non raggiungono Pi-hole: apri il firewall di Windows. Da PowerShell come amministratore: 
    New-NetFirewallRule -DisplayName "Pi-hole DNS UDP" -Direction Inbound -Protocol UDP -LocalPort 53 -Action Allow
    New-NetFirewallRule -DisplayName "Pi-hole DNS TCP" -Direction Inbound -Protocol TCP -LocalPort 53 -Action Allow
  • Nella dashboard tutti i dispositivi compaiono come uno solo: è un limite di Docker Desktop, il blocco funziona lo stesso. Per vederli separati serve Pi-hole su Linux, anche in una macchina virtuale
  • Hai dimenticato la password: impostane una nuova con docker exec -it pihole pihole setpassword
  • Il container non parte: leggi i log con docker compose logs --tail 50
  • Un dispositivo aggira il blocco: togli il DNS secondario, o rimettici l'IP di Pi-hole. Controlla anche il DNS privato di Android e il DNS sicuro del browser
